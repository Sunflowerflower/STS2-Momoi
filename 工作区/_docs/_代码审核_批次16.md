## 一、已修复（9 项）

### 🔴 1. 两处悬停即崩：给不可升级的牌预览升级版

`HoverTipFactory.FromCard<T>(upgrade: true)` 内部会 `card.UpgradeInternal()`，而
`CardModel` 的 `CurrentUpgradeLevel` setter 是：

```csharp
if (value > MaxUpgradeLevel)
    throw new InvalidOperationException($"{Id} cannot be upgraded past its MaxUpgradeLevel.");
```

诅咒 / 状态牌的 `MaxUpgradeLevel == 0`，所以传 `true` 必抛：

| 位置 | 牌 | 原版 MaxUpgradeLevel |
|---|---|---|
| `Cards/BurnFlowCards.cs:94` | 玩火+ 预览「灼烧」 | `Burn` = **0** |
| `Cards/MinigameFlowCards.cs:197` | 熬夜+ 预览「睡眠不佳」 | `PoorSleep` = **0** |

**修法**：这两处恒传 `upgrade: false`（其他 36 处 `FromCard<X>(IsUpgraded)` 都逐一核过，目标卡都可升级）。

> 这类「用未校验参数调用会抛的原版 API」是本次审核里唯一**必崩**的两条。

### 🔴 2. 俄罗斯方块：少了「把弃牌堆的方块返回手牌」

卡面写「…将[gold]弃牌堆[/gold]的所有[gold]方块[/gold]返回[gold]手牌[/gold]」，
但 `TetrisFullHandPower.Settle` 里那趟循环在批次13 重写时被删掉了 ——
而**溢出方块恰恰就躺在弃牌堆**（`Tetris.OnPlay` 在手牌满时把方块放进 `Discard`）
→ 最常见的触发场景下效果完全没发生。已补回。

### 🔴 3. 集结的减费漏算绝大多数「支援牌」

`CombatStats.SupportCardsPlayed` 的唯一写点用的是
`MinigameSupport.IsSupportCard(card)` = **只看 tag**，
而模组里大部分支援牌**没有 tag**（只有 `IsSupportCardType` 认得它们）
→ 打出「来自歌原的援助」这类牌时，集结根本不减费。

**修法**：改成 `IsSupportCard(card) || IsSupportCardType(card)`（与侧栏判定同一套规则）。

### 🔴 4. 集结的减费被减两次（我上一批引入的回归）

批次15 我把集结改成 `TryModifyEnergyCostInCombat` 现算，
但 `CombatStats.MinigamePlayedPatch` 里**还留着旧写法**：
每打出一张支援牌就给手里每张集结 `AddThisCombat(-1)`
→ 现算减一次 + 追加减一次 = **减 2 倍**。已把补丁里那段删掉。

### 🟠 5. 「雷酱」快照可能多吃一次易伤

`FaceDamage` 原本直接读 `DynamicVars.CalculatedDamage.PreviewValue`。
`PreviewValue` 是**展示值**，由 `Hook.ModifyDamage(... target ...)` 带目标算出来 ——
如果卡面最后一次重绘时带着易伤目标，它已经乘过 1.5，而本 power 自己还会再补一次易伤
→ 最坏 1.5×1.5。

**修法**：`FaceDamage` 改成自己重算同一条管道、但 `target` 传 `null`
（易伤/虚弱这类需要目标的修正就不会介入），力量/活力照常算进去。

### 🟠 6. 双刀王小桃重复打出时对死目标空放

```csharp
for (...) { var dupe = CreateDupe(player); await CardCmd.AutoPlay(ctx, dupe, target); }
```
`target` 是 OnPlay 开头抓的，前几次重复很可能已把它打死；
而 `AutoPlay` 对**非 null** 目标不做存活检查 → 后续重复静默空放（卡被消耗、无伤害）。
改成 `target is { IsAlive: true } ? target : null`（让 AutoPlay 自己重挑）。

### 🟠 7. 心流 / 剑来！的减费语义与文案不符

| 卡 | 问题 | 修法 |
|---|---|---|
| 心流 | 文案「此牌的耗能在下一次打出前减少 2c」= 单次覆盖；但 `AddUntilPlayed` 是**追加**型相对修正，同回合触发两次变 -4（基础 3 费被钳成 0） | 改 `SetUntilPlayed(Canonical - reduce)`（覆盖式） |
| 剑来！ | 文案「使其**本回合**耗能减少 1c」；`AddUntilPlayed` 只在**打出**时清理，没打出去会留到下一回合 | 改 `AddThisTurnOrUntilPlayed` |

### 🟠 8. 火焰附加把「升级 2 层」硬编码

`data.BurnAmount += amount * (cardSource?.IsUpgraded == true ? 2 : 1)` ——
卡面数值在 `DynamicVar("Burn", 1)` 里，两边一旦不同步就会脱节（且 `cardSource` 为 null 时静默按 1 算）。
改成读来源卡的 `BurnPerStack`。

### 🟢 9. 其它小修

- **非战斗时 `GetPile` 会抛**：`ConceptCounterCapability` 的 4 个静态 helper、`CyclicNarrative.ShuffleDiscardsEnteredThisTurn`
  改用 `CardPile.Get`（返回 null）。
  （原先的调用点都在战斗内，属于**脆弱但暂时安全**，改成 null 安全可防未来误用。）
- **空引用警告**：`RemainingCards2.cs`（`Owner.PlayerCombatState?.Energy`）、`RemainingCards3.cs` ×2、
  `RemainingCards5.cs`（`player` 判空）、`RemainingSpecialCards.cs`、`MoreRelics.cs` 的 `TurnNumber` 都加了 `?.`。
- **`ThrowingPlayerChoiceContext` 用错地方**：它 `SignalPlayerChoiceBegun` 直接抛 `NotImplementedException`；
  凡是**钩子本来就给了真实 `choiceContext`** 的地方（俄罗斯方块结算、节奏游戏伤害、重整旗鼓自动打出）
  已改用真实上下文；剩下的是「钩子签名里根本没有上下文」（`AfterPreventingDeath`、`BeforeCombatStart` 等），保留不动。
- **`"Cards"` 变量类型**：`DynamicVarSet.Cards` 在原版是**强转** `CardsVar`，
  普通 `DynamicVar("Cards", n)` 只要有人读 `DynamicVars.Cards` 就 `InvalidCastException`；
  `BA启动！` 已改用 `CardsVar`。

## 二、**没有改**，需要你拍板的（4 项）

### 1. 机会难得，选红色！有一段「卡面没写的免费」

```csharp
picked.EnergyCost.SetUntilPlayed(0);   // 代码给了：下次打出免费
```
卡面只有「从两张随机红色牌中选择一张加入你的手牌。」——**没有任何减费说明**。
（代码上方的注释写的是「本场战斗免费打出」，与 `SetUntilPlayed` 的「直到打出」语义也不一致。）
二选一：**删掉这行**，或**把描述补上**（如「…加入你的手牌，这张牌在下一次打出前耗能为 0。」）。

### 2. 来自明日奈的援护：减伤是否应该挡灼烧/中毒这类 DoT？

现在 `ModifyDamageMultiplicative` **不看 `props`**，所以对**所有**伤害生效（含 `Unpowered`/`Unblockable`）。
原版同类效果都做了门控：

```csharp
// ColossusPower / VulnerablePower / WeakPower 都是这样
if (!props.IsPoweredAttack()) return 1m;
```
而卡面/侧栏文案是「你受到的**所有**伤害降低 25%」。→ 按文案就该挡 DoT，按原版惯例就不该。
我暂时**按文案保留**（不改），你确认一句我就改。

### 3. 心流：减费是「覆盖」还是「可叠加」？

我改成了**覆盖式**（同回合多次触发仍是 -2，与文案「减少 2c」一致）。
如果设计意图是「每 3 张小游戏牌再 -2」（可叠到 0 费），说一声我改回 `AddUntilPlayed` 并补注释。

### 4. 自动打出被「阻止」时，是否还算触发？

`CardCmd.AutoPlay` 有几条**静默不打出、只把牌挪走**的路径：
`Unplayable` 关键字、`Hook.ShouldPlay` 被阻止（如「凡庸」类限制）、`AnyAlly` 但没有存活队友。

受影响的卡：
- **蒙太奇**：牌没打出去，但仍然照样 +1 构想 / 塞一张构想
- **王道 / 严守截稿日**：`CardPileCmd.Add(this, Hand)` 手牌满时会**静默进弃牌堆**，而「返回手牌」的减费照样挂上

要不要加「确认真的打出去了才算数」的判断？加了更严谨，但会改到数值手感，所以留给你定。

## 四、复核结论：这些**写法是对的**（避免以后重复排查）

- **`IsClone` 而不是 `IsDupe`** 确实能同时覆盖 `CreateClone` 与 `CreateDupe`（两者都走 `_cloneOf`）。
- **渔获 / 秒人斧**的「打出时从牌组移除」链路完整：`RemoveFromDeck` 的全部前置条件（`Pile?.Type == Deck`、
  `IsClone` 判断、`DeckVersion` 回退）都满足；升级走 `UpgradeInternal` 绕开了 `CardCmd.Upgrade` 在 `IsEnding` 时的早退。
- **`RankUpPower` 换「掉到二档了」** 不会在战斗胜利时重复发奖（胜利走 `RemoveAllPowersInternalExcept`，**故意跳过** `AfterRemoved`）。
- **`BattleRoyale` 的 `CalculatedVar` 里调 `GetPile`** 不会在图鉴/牌组界面炸 —— `CalculatedVar.Calculate` 只在
  `CombatManager.Instance.IsInProgress && CombatState != null` 时才调乘数。
- **`MyTurnPower`** 与原版 `AmbergrisPower` 逐行对应。
- **扫雷「抽到炸弹直接打出」** 不会静默失效（`TheBomb` 是可打出的 2 费技能，没有 `Unplayable`）。
- **`AutoPlay(..., null)`** 在 `AnyEnemy` 没有合法目标时会走 `MoveToResultPileWithoutPlaying`，不会抛。
- **跨战斗状态**由 `Hook.BeforeCombatStart` → `CombatStats.Reset()` 统一重置（含 `GrindingCursePool`）；
  `RunStats` 由 `Entry` 在 RunStarted 重置。
- **订阅**只有 2 处（`KinglyWayRebateCapability` 的 `card.Played`、`RallyAgainPower` 的 `MaxHpChanged`），
  后者在 `AfterRemoved(Creature oldOwner)` 里正确退订；前者随卡实例一起消亡。
