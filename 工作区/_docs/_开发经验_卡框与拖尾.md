# 开发经验：卡框与卡牌拖尾

> 基于 2026-10-23 的两次调试 + RitsuLib QA 总结。
> 这次踩的坑：**只改 `CardPoolModel.PoolFrameMaterial` 只能覆盖“视觉卡池”是该池的卡**；TokenCardPool 里的技能/能力/支援牌仍然走 TokenCardPool 的材质，所以会出现“攻击牌有渐变、技能/能力牌外框还是深色”。另外卡框材质作用于整张 Frame（含文字框背景），必须单独压暗正文区，不能整块浅渐变。

## 1. 卡框由哪些独立部位组成

RitsuLib `CardAssetProfile`：

| 部位 | 作用 | 原版对应 |
|---|---|---|
| `FramePath` | 卡框本体：整体外框 + 底纹 | `ui_atlas/card_frame_{attack|skill|power}_s.tres` |
| `PortraitBorderPath` | 立绘边框；状态/诅咒感染效果 | `card_portrait_border_*_s.tres` |
| `BannerTexturePath` | 标题横幅底图 | 原版横幅贴图 |
| `FrameMaterialPath` | 卡框上色 | `materials/cards/frames/card_frame_*_mat.tres` |
| `BannerMaterialPath` | 横幅上色 | `materials/cards/banners/card_banner_{rarity}_mat.tres` |
| `EnergyIconPath` | 费用图标 | 对应卡池能量图标 |

实际显示节点（`NCard.cs`）：

- `%Frame`
- `%PortraitBorder`
- `%TitleBanner`
- `%TypePlaque`

先古卡另走：`AncientBorder` / `AncientTextBg` / `AncientBanner`。

## 2. 原版 getter 行为

- `CardModel.Frame` 根据 `Type` 取 `card_frame_{attack|skill|power}_s.tres`。
- `CardModel.FrameMaterial => VisualCardPool.FrameMaterial` —— **关键**：不是按角色 ID，而是按**这张牌当前的 VisualCardPool**。
- `BannerMaterial` 按**稀有度**取 `card_banner_{rarity}_mat.tres`。
- 因此：
  - 主池卡（`STS2_MomoiCardPool`）会拿到我们池子的材质；
  - TokenCardPool / 其他池的卡不会，除非额外 patch `CardModel.FrameMaterial`。
- 解决方案：`Patches/MomoiCardFrameMaterialPatch.cs` 拦截 `CardModel.get_FrameMaterial`，对 `Id.Entry` 以 `STS2_MOMOI_` 开头的所有卡返回同一个渐变材质。这样支持 TokenCardPool 的技能/能力/支援牌。
- `BannerMaterial` / `PortraitBorder` 完全不动，稀有度表现保持原版。

## 3. 卡框渐变设计要点

- 原版卡框不是一张普通 PNG，而是 **类型帧 atlas + SDF EXR + HSV/自定义 shader**。
- 当前 shader：`shaders/momoi_card_frame_gradient.gdshader`
  - 左 `#F5BFD6` → 右 `#BDD6FA`，`UV.x` 线性插值。
  - 用原图亮度保留凹槽/高光/黑描边。
  - **外框**全部渐变：三种类型 attack/skill/power 都生效。
  - **正文框/背景**：`UV.y` 内部区域使用深色底 + 少量渐变；原图较亮的文字框描边保留一点渐变。
  - 底部外框从正文遮罩中排除，避免“只有上面有渐变”的错觉。
  - 黑描边保留；文字使用奶油色，正文区足够暗。
- 原版卡面尺寸：普通卡 **250×190**；先古卡 250×351 左右。
- 展示节点尺寸 300×422；类型帧 atlas 区域约 598×844（ancient 618×862）。
- 稀有度框/横幅不要跟卡框材质混在一起：`BannerMaterial` 按稀有度取，保持原版。

## 4. 卡牌拖尾

`CharacterVfxAssetSet`：

- `TrailPath`：拖尾 VFX 场景。
- `TrailStyle`：颜色/宽度覆盖。

可调项（`CharacterTrailStyle`）：

- `OuterTrailModulate` / `OuterTrailWidth`
- `InnerTrailModulate` / `InnerTrailWidth`
- `BigSparksColor` / `LittleSparksColor`
- `PrimarySpriteModulate` / `PrimarySpriteScale`
- `SecondarySpriteModulate` / `SecondarySpriteScale`

原版 `card_trail_ironclad.tscn` 结构：

- `OuterTrail`：Line2D，宽度 96，透明度较高 → 最显眼。
- `InnerTrail`：Line2D，宽度 64，较细。
- `BigSparks` / `LittleSparks`：粒子。
- `Sprite2D2/3`：卡牌剪影。

经验：

- 蓝色不明显，通常是因为**宽的外轨迹是粉色、窄的内轨迹才是蓝色**。
- 这次改为：**外轨迹蓝 `#8FB8FF`（宽，主导）**，内轨迹粉 `#F5A9C9`（窄）；大小火花/主副精灵同色系。这样蓝色立刻可见。
- 只换颜色不需要新贴图；要换整体形状才需要自定义 `card_trail_*.tscn`。
- 如果以后要真·沿轨迹渐变（而不是外/内双色），需要给 Line2D/粒子加自定义 shader，`CharacterTrailStyle` 做不到。

## 5. 调试顺序

1. 先确认卡牌的 `VisualCardPool` 是谁：主池/TokenCardPool/无色池。
2. 外框不对 → 先查 `CardModel.get_FrameMaterial` 是否覆盖到这张卡。
3. 文字框太亮/太暗 → 只调卡框 shader 的正文区遮罩和 `bodyTint`，不要动 `BannerMaterial`。
4. 稀有度框不对 → 看 `BannerMaterial` / `PortraitBorder`，不是 `FrameMaterial`。
5. 拖尾颜色不对 → 先看 `OuterTrail`（宽）和 `InnerTrail`（窄）分别是什么颜色，再看 `CharacterTrailStyle`。

## 6. 补充教训：只 patch `CardModel.FrameMaterial` 不一定会生效

这次实际游戏里“预览对、游戏不对”的最后根因：

- RitsuLib/原版自己也对 `CardModel.FrameMaterial` 挂了 **Prefix**，会在某些卡/卡池上直接给 `__result` 赋值并跳过原方法。
- 我们只加 Postfix，虽然属性最终值在模型层看起来对，但 `NCard.Reload()` 里还有别的时序/覆盖点，实际 `%Frame` 可能仍拿到旧材质。
- 更稳的兜底：**直接 patch `NCard.Reload`**，在它执行完后：
  ```csharp
  var frame = __instance.GetNodeOrNull<TextureRect>("%Frame");
  if (frame != null) frame.Material = gradientMaterial;
  ```
- 只看构建/预览不够；卡框这种“模型 getter + 节点材质”的双层链路，必须验证最终节点。

结论：卡框生效链路 = `CardModel.FrameMaterial` → `NCard._frame.Material`。
只改前者可能被 Prefix 覆盖；直接在 `NCard.Reload` 后改 `%Frame` 才能保证实际画面。


## 7. 最终根因：`%Frame` 是 AtlasTexture，shader 的 UV 是整张图集坐标

前一版“预览对、游戏里还是深色/金色”的真正原因不是 `%PortraitBorder`：

- `%Frame.Texture` 是 `AtlasTexture`（例如 `card_frame_power_s.tres` 的 region 是 `Rect2(621, 929, 598, 844)`）。
- 在 canvas shader 里，`UV` 是**整张 `ui_atlas_0.png` 的归一化坐标**，不是卡框 region 的 0..1。
- 旧 shader 直接拿 `UV.y` 做正文遮罩：图集里 y≈0.45~0.87 全被判为 body，于是**整张卡框都被压成 `bodyTint` 深紫**；`UV.x` 也几乎落在图集右侧，粉→蓝渐变看起来只剩暗紫。离线渲染一张 700×900 的 Frame 就能复现，和实际游戏完全一致。
- 这也解释了为什么预览图是对的：预览用的是裁好的 region 图，UV 天然 0..1；游戏用的是 AtlasTexture。

修复：

1. shader 增加：
   ```glsl
   uniform vec2 uv_offset = vec2(0.0, 0.0);
   uniform vec2 uv_scale = vec2(1.0, 1.0);
   vec2 card_uv = (UV - uv_offset) / max(uv_scale, vec2(0.0001));
   ```
   surface 渐变和 body 遮罩全部改用 `card_uv`；`texture(TEXTURE, UV)` 仍用原 UV 采样。
2. `NCard.Reload` 的 Postfix 里，按卡牌实际的 `AtlasTexture` 动态计算：
   ```csharp
   var size = atlas.Atlas.GetSize();
   material.SetShaderParameter("uv_offset", atlas.Region.Position / size);
   material.SetShaderParameter("uv_scale", atlas.Region.Size / size);
   ```
   因为 attack/skill/power 三个 region 不同，material 必须**每张卡 Duplicate 一份**再写参数，不能共用 `.tres`。
3. `%PortraitBorder` 和 `%TitleBanner` **完全不动**：用户明确要求稀有度边框/横幅保持原版；之前试过把 `PortraitBorder` 也改渐变，已回退。

验证方式：不启动游戏，用 Godot 加载 `ui_atlas_0.png` + 三个真实 region + 新 shader，按实际 region 设置 `uv_offset/uv_scale` 渲染三张 300×422；结果应和 `_work/momoi_card_frame_types_preview.png` 一致（亮粉蓝外框 + 深色正文）。

结论：卡框链路有三层，缺一不可：
- `CardModel.FrameMaterial`（模型层）
- `NCard.Reload` 后覆盖 `%Frame.Material`（节点层）
- shader 里把 **AtlasTexture 的 region UV** 归一化（纹理层）
