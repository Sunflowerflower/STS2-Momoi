# 开发经验：残血 low_hp 动画 + 残血 BGM

> 2026-10-23；王小桃。涉及 `STS2 MomoiCharacter.cs`、`Patches/MomoiLowHpPatch.cs`、
> `images/characters/cue/low_hp*.png`、`audio/low_hp_bgm.ogg`。

## 1. 残血帧：从 idle 删蹲起，而不是重做一套

- 现有 idle 结构：`IdleLoop`（13 个唯一站立帧，3 轮）+ `IdleOutro`（收尾，其中
  `16-19 / 24-28 / 33-37` 是三组蹲起）。
- 残血版保留完整 idle 结构，只跳过 `IsIdleCrouch(frame)` 的三个帧组：
  - 前 3 轮 `IdleLoop` 原样保留（同一批 low_hp 图）；
  - 收尾只保留 `IdleOutro` 中非蹲起的 15 组。
- 结果：28 个唯一帧，`LowHpFrameMap` 映射原 idle 帧号 -> low_hp 序号（蹲起帧为 -1）。
- 关键：**不要在 C# 里手写帧号/时长**。`_build_low_hp_cue.py` 读 `idle_manifest.json`
  的 `file` 名来取唯一帧序号；不能用 `rep_frame`（outro 的 `rep_frame` 是 AE 绝对帧 138..192，
  不是 13..41，直接拿会过滤错）。生成 `_work/low_hp_csharp.txt` 后粘贴到 C#。

## 2. 汗滴：画风 + 位置

- 画风跟人物一致：深棕/黑粗描边、平涂浅蓝、白高光；尺寸 22×29（600×820 画布）。
- 位置：**左脸颊靠边**，避开左眼和嘴；每帧按角色 alpha bbox 的 `(left, top)` 相对 idle 帧 0
  偏移，身体上下浮动时汗滴仍留在脸上。
- 第一版曾把汗滴画在右眼附近，读起来像眼泪/眼部装饰；改到左脸颊边缘后更像汗。
- 联系表：`工作区/编辑区/人物/_work/low_hp_contact.png`；不满意只改 `_build_low_hp_cue.py`
  的 `BASE_ANCHOR`，别改已生成的图。

## 3. 状态机：low_hp 循环状态

- `VisualCues` 加 `.Sequence("low_hp", ...).Loop()`；`SetupCustomCombatAnimationStateMachine` 加：
  ```csharp
  b.AddState("low_hp", true).Done();
  b.AddAnyState("LowHp", "low_hp");
  ```
- 攻击/受击/施法状态的 `WithNext("idle")` **不需要改**；它们自然结束后，控制器看到当前
  状态回到 `idle` 且仍残血，再发 `LowHp`。这样不会在攻击中途硬切残血待机。
- 回血离开 25% 时，如果当前是 `low_hp`，发 `Idle` 切回正常 idle。
- 触发条件用 `Creature.GetHpPercentRemaining() <= 0.25`（和原版 `IsLowHealth` 阈值一致）。

## 4. 为什么不用 CharacterModel 的 AfterCurrentHpChanged

- `CharacterModel.ShouldReceiveCombatHooks` 在游戏里是 **false**，而且 `CombatState.IterateHookListeners`
  只收 Power / Relic / Potion / Card / Modifier 等，**不会遍历玩家 CharacterModel**；
  直接 override `AfterCurrentHpChanged` 不会被调用。
- 可选方案是 `ModHelper.SubscribeForRunStateHooks` 返回角色模型，或加一个隐藏 Power/Relic；
  但为了不往 UI 里加能力/遗物，这里直接在 `NCreature._Ready` 后挂一个轻量 Node 轮询。
- `NCreature` 会有池化/复用；控制器以 `Creature.CombatState` 对象是否变化来重置状态，
  并在 `CombatState == null` / `IsDead` 时停止音频，避免上一场残留。

## 5. 残血 BGM：2 分钟一遍，不能 PlayLoop

用户要求：**播完一遍再判断是否仍残血，离开残血不能截断当前这一遍，战斗结束停止**。

- `SfxCmd.PlayLoop + StopLoop` 会在离开阈值时淡出停止，**做不到**播完整一遍，不能用。
- 用挂在 `NCreature` 下的 `AudioStreamPlayer`：
  - `Bus = "SFX"`；
  - OGG 导入 `loop=false`（本项目 `low_hp_bgm.ogg.import` 已是 false）；
  - 进入残血时如果没有在播，就 `Play()`；
  - 连 `Finished`：回调里若仍残血且战斗仍有效，再 `Play()`；否则不续播；
  - 离开残血只把 `_low=false`，**不 Stop**；
  - 死亡 / `CombatState == null` / `_ExitTree` 才 Stop；
  - 奖励界面（`NOverlayStack.Instance.Peek() is NRewardsScreen`）出现时，不等 CombatState 清空，
    `AudioStreamPlayer.VolumeDb` 从当前设置音量线性降到 -80，**2 秒**后 Stop；死亡和战斗结束也走同一套 2 秒淡出，不硬切。
- 不要每次扣血都重新 `Play()`：那样会叠加/重头，应该只在跨入残血且当前未播时启动。

## 6. 读取 RitsuLib 状态机

- 不再反射 RitsuLib 内部补丁类。新增 `MomoiAnimMachineTrackPatch`，同时 patch
  `ModAnimStateMachine.Start` 和 `ModAnimStateMachine.SetTrigger`，在 Postfix 里用
  `__instance.Backend.OwnerNode` 作为 key，把状态机登记到 `MomoiAnimMachineRegistry`
  （`ConditionalWeakTable<Node, ModAnimStateMachine>`）。
- 控制器用 `NCreature.Visuals`（以及 `NCreature` 兜底）查询注册表，读 `Current.Id`。
- 为什么之前只有 BGM、没有 low_hp：旧版反射拿不到内部补丁类型时返回 null，控制器
  就不会发 `LowHp`；BGM 不依赖状态机，所以正常。改成显式登记后，`[LowHp]` 日志会显示
  `machine=True/current=.../hasTrigger=True/hasAnim=True`，残血 idle 正常切换。
- 新增一个补丁后总数为 **24**。

## 7. 音量设置

- 设置页「音量」有六个滑块：总音量、音乐音量、语音音量、音效音量、受击语音音量、死亡语音音量（死亡默认 500%，最高 700%）。
- `MomoiAudio` 在每次播放前用 `总音量 × 分类` 更新 virtual event 注册音量；残血 BGM 用 `MusicGain` 写 `AudioStreamPlayer.VolumeDb`。
- 0% 用 -80 dB / 0.0001 增益静音；淡出期间不再覆盖音量，淡出结束后恢复设置值。

## 8. 验证清单

1. 战斗开始 HP 已 ≤25%：直接播 low_hp idle + BGM。
2. 战斗中扣到 ≤25%：当前 idle → low_hp；攻击中不硬切，攻击结束回 low_hp。
3. 治疗到 >25%：回正常 idle；**BGM 当前这一遍继续播完**，播完不续。
4. 仍残血时 BGM 播完：自动再播一遍。
5. 奖励界面 / 死亡 / 战斗结束：BGM 2 秒淡出后停止；死亡语音由 `CreatureDiedEvent` 独立触发（死亡音量，覆盖战斗/事件/主动放弃）。选人 BGM 由背景场景内的 AudioStreamPlayer 播放，走 `MusicVolumeDb`。
6. 最终建筑师对话场景（`TheArchitectEventEncounter`）：不播放残血 BGM；若正在播，2 秒淡出。
7. 28 张 low_hp 帧都应有一滴汗，且三组蹲起不再出现。
